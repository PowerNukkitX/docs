Migrating from Dragonfly to PowerNukkitX means moving from a Go codebase to a Java one. World data ports over directly, but Dragonfly's server logic is compiled Go code, so any custom behavior has to be rebuilt with the PowerNukkitX plugin API.

## Step-by-Step Migration

### 1. Set Up PowerNukkitX
Install a fresh PowerNukkitX server. Follow the [Installation](/docs/installation) guide for your operating system. Start the server once to generate configurations and then stop it.

### 2. Migrate Worlds
Dragonfly uses the same LevelDB world format as the Bedrock client.
1. Find the world folder set by `Folder` under `[World]` in Dragonfly's `config.toml` (default `world`).
2. Copy that folder into the PowerNukkitX `worlds/` directory and rename it to the level name you want.
3. Open `pnx.yml`, navigate to `settings`, and set `defaultLevelName` to that folder name:
   ```yaml
   settings:
     defaultLevelName: "MyWorld"
   ```

### 3. Translate Configuration
Dragonfly keeps everything in `config.toml`. Map the values to `pnx.yml` by hand:

| Dragonfly Setting (`config.toml`) | pnx.yml Category | pnx.yml Key | Description |
| :--- | :--- | :--- | :--- |
| `[Network] Address` (e.g. `:19132`) | `settings` | `ip` + `port` | Host before the colon, port after. Empty host maps to `0.0.0.0`. |
| `[Server] Name` | `settings` | `motd` | Server name shown in the list. |
| `[Players] MaxCount` | `settings` | `maxPlayers` | Max player slots. Dragonfly `0` means unlimited - set a concrete number in PNX. |
| `[Server] AuthEnabled` | `settings` | `xboxAuth` | Requires Xbox authentication. |
| `[World] Folder` | `settings` | `defaultLevelName` | Copied into `worlds/`, see step 2. |

<Callout type="info">
    In PowerNukkitX `gamemode` and `difficulty` under `gameplay-settings` are integers (gamemode `0`-`3`, difficulty `0`-`3`). Set them to match how your Dragonfly world played.
</Callout>

## Critical Incompatibilities

### Go Code vs Java Plugins
Dragonfly is a framework: your server's behavior lives in Go source compiled into the binary, not in loadable plugins. None of that runs on PowerNukkitX.
- You cannot drop Go code or a compiled Dragonfly binary into the `plugins/` folder.
- **Action:** Rebuild your features as PowerNukkitX plugins in Java. Start from [Create a plugin](/docs/development/basics). Many common needs already exist as community plugins, so check those first.

### Permissions
Dragonfly handles permissions in code. PowerNukkitX uses a standard Java permission architecture.
- For group permissions, install the **LuckPerms** plugin and recreate your groups and nodes. See the [Permissions & Security](/docs/permissions) page.

### Player Data
Player inventories and positions are stored inside the LevelDB world, so they travel with the world folder. Plugin-specific data (economy, kits, homes) does not - export it from the old setup and import it into the replacement plugin.

## Migrating Server Code

Dragonfly is a framework: you write Go and compile it into the server binary. PowerNukkitX is a server that loads Java plugins at runtime. The programming model is different, so your server logic has to be rewritten as one or more Java plugins. The mapping below shows the common patterns.

### Entry point

```go
// Dragonfly (Go) - your main package
func main() {
    conf := server.DefaultConfig()
    srv := conf.New()
    srv.Listen()
    for srv.Accept(func(p *player.Player) {}) {
    }
}
```

```java
// PowerNukkitX (Java) - a plugin, not a main()
import org.powernukkitx.plugin.PluginBase;

public class MyPlugin extends PluginBase {
    @Override
    public void onEnable() {
        getLogger().info("Enabled!");
    }
}
```

You do not manage the server loop yourself. PowerNukkitX runs it; your plugin hooks into lifecycle methods (`onLoad`, `onEnable`, `onDisable`) and events.

### Handling events

Dragonfly attaches a `Handler` to a player to react to actions. PowerNukkitX uses a `Listener` with `@EventHandler` methods.

```go
// Dragonfly (Go)
func (h *MyHandler) HandleBlockBreak(ctx *event.Context, pos cube.Pos, drops *[]item.Stack, xp *int) {
    // react to a block break
}
```

```java
// PowerNukkitX (Java)
import org.powernukkitx.event.EventHandler;
import org.powernukkitx.event.Listener;
import org.powernukkitx.event.block.BlockBreakEvent;

public class MyListener implements Listener {
    @EventHandler
    public void onBreak(BlockBreakEvent event) {
        // react to a block break
    }
}
```

Register it in `onEnable`:

```java
getServer().getPluginManager().registerEvents(new MyListener(), this);
```

Dragonfly's `event.Context.Cancel()` maps to `event.setCancelled(true)` on a cancellable PowerNukkitX event.

### Blocks and items

Dragonfly uses typed Go structs (`block.Stone{}`, `item.Sword{}`). PowerNukkitX resolves content by Bedrock **string identifier** through `BlockID` and `ItemID`.

```java
import org.powernukkitx.block.Block;
import org.powernukkitx.block.BlockID;

Block stone = Block.get(BlockID.STONE); // "minecraft:stone"
```

### Commands

Dragonfly registers commands with `cmd.Register`. In PowerNukkitX a command extends `Command` (optionally declared with `@CommandDefinition`) and is registered on the command map:

```java
getServer().getCommandMap().register("myplugin", new HelloCommand());
```
