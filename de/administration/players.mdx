Wer auf deinem Server was darf: Operatoren, Whitelist, Kicks und Banns, und was der Offline-Modus ändert.

## Operatoren

Operatoren überspringen Berechtigungsprüfungen und können jeden Befehl ausführen.

```bash title="Console"
op <player>
deop <player>
```

Sie stehen in `ops.txt`, ein Name pro Zeile; die Datei kannst du bei gestopptem Server bearbeiten. Über ein paar vertrauenswürdige Admins hinaus nutzt du ein Berechtigungs-Plugin: siehe [Berechtigungen & Sicherheit](/docs/de/permissions).

## Whitelist

Lass nur freigegebene Spieler herein. Schalte sie in `pnx.yml` ein:

```yaml title="pnx.yml"
baseSettings:
  allowList: true
  allowListMessage: Server is white-listed
```

Dann können nur Spieler aus `white-list.txt` beitreten; alle anderen werden mit `allowListMessage` gekickt. Verwalte sie mit:

```bash title="Console"
whitelist add <player>
whitelist remove <player>
whitelist list
```

<Callout type="info">
  Mit eingeschaltetem `xboxAuth` (Standard) werden Spieler über ihr Xbox-Konto erkannt, ein geänderter Anzeigename umgeht die Whitelist also nicht.
</Callout>

## Kicks und Banns

| Befehl | Wirkung |
| :-- | :-- |
| `kick <player> [reason]` | Trennt einen Spieler sofort. Er kann zurückkommen. |
| `ban <player> [reason]` | Bannt einen Spieler über seinen Namen. |
| `pardon <player>` | Hebt einen Namensbann auf. |
| `ban-ip <address\|player>` | Bannt eine IP-Adresse. |
| `pardon-ip <address>` | Hebt einen IP-Bann auf. |

Banns werden in `banned-players.txt` und `banned-ips.txt` gespeichert.

## Offline-Modus

Setzt du `baseSettings.xboxAuth` auf `false`, ist die Xbox-Authentifizierung aus.

<Callout type="error" title="Nur in vertrauenswürdigen Netzwerken">
  Ohne Authentifizierung kann jeder unter jedem Namen beitreten, und Whitelist und Banns lassen sich leicht umgehen. Nutze den Offline-Modus nur im LAN oder hinter einem Proxy, der die Spieler authentifiziert (siehe [WaterdogPE](/docs/de/integrations/wdpe)).
</Callout>
