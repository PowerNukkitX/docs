## init [#init]

Legt einen Server an: einen Ordner, die PowerNukkitX-Jar und die Startskripte. Aliase: `new`, `create`.

```bash
pnx init
pnx init --dir my-server
pnx init --version 1.21.0
```

| Option | Wirkung |
| :-- | :-- |
| `--dir <pfad>` | Der Ordner, in dem der Server angelegt wird. |
| `--version <tag>` | Ein PowerNukkitX-Release-Tag, das die Versionsauswahl überspringt. |

Im Terminal fragt es nach dem, was fehlt; in einem Skript (oder mit `--json`) läuft es ohne Fragen. Die Jar kommt aus den GitHub-Releases von PowerNukkitX, die Skripte aus [PowerNukkitX/scripts](https://github.com/PowerNukkitX/scripts). Der neue Server wird zum Standardserver.

## start [#start]

Startet den Server im Vordergrund, mit den Java-Flags, die PowerNukkitX braucht. Aliase: `run`, `up`.

```bash
pnx start
pnx start --memory 4G
pnx start --restart
pnx start --dry-run
```

| Option | Wirkung |
| :-- | :-- |
| `--dir <pfad>` | Der Serverordner statt des Standardservers. |
| `-m`, `--memory <größe>` | Java-Heap beim Start, standardmäßig `2G`. |
| `--restart` | Startet den Server erneut, wenn er mit einem Fehler endet. |
| `--dry-run` | Gibt den `java`-Befehl aus, statt ihn auszuführen. |

`pnx start` startet Java durchgehend mit UTF-8, dem Garbage Collector ZGC, den Flags `--add-opens` und `-XX:MaxRAMPercentage=75.0`, sodass der Heap auf drei Viertel des Arbeitsspeichers wachsen kann. Es nutzt das Java aus `JAVA_HOME`, wenn es gesetzt ist.

## stop [#stop]

Stoppt den Server, den `pnx start` gestartet hat, über die Prozess-ID, die es sich gemerkt hat. Alias: `down`.

```bash
pnx stop
```

<Callout type="info">
  Für ein sauberes Beenden von innen tippst du `stop` in die Serverkonsole: Vorher wird alles gespeichert.
</Callout>

## console [#console]

Öffnet eine Konsole zu einem laufenden Server, über **RCON**.

```bash
pnx console
```

Sie liest `enable-rcon`, `rcon.port` (standardmäßig `25575`) und `rcon.password` aus der `server.properties` des Servers. RCON ist standardmäßig aus; dann sagt dir `pnx console`, was du einschalten musst. Mit `exit` verlässt du sie.

## logs [#logs]

Gibt das Serverlog aus und verfolgt es weiter. Alias: `log`.

```bash
pnx logs
pnx logs --lines 200
pnx logs --no-follow
```

| Option | Wirkung |
| :-- | :-- |
| `-n`, `--lines <n>` | Wie viele Zeilen zuerst angezeigt werden. |
| `--follow` | Gibt neue Zeilen laufend aus. `--no-follow` gibt aus und beendet. |

## config [#config]

Zeigt die Konfiguration, die der Server liest, damit du einen Wert prüfen kannst, ohne die Datei zu öffnen.

```bash
pnx config
```

## use [#use]

Wählt den Server, auf dem alle Befehle arbeiten.

```bash
pnx use
pnx use ./my-server
pnx use --clear
```

Ohne Ordner listet es die gefundenen Server auf und lässt dich wählen. `--clear` vergisst den Standard wieder.
