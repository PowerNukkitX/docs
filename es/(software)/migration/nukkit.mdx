Es la migración más sencilla: PowerNukkitX lee tu configuración antigua y la convierte en el primer arranque.

## Pasos

<Steps>
  <Step>
    ### Haz una copia de seguridad

    Copia toda la carpeta del servidor en un lugar seguro.
  </Step>
  <Step>
    ### Sustituye los archivos

    1. Descarga el último `powernukkitx.jar` desde las [releases](https://github.com/PowerNukkitX/PowerNukkitX/releases).
    2. Descarga el script de inicio de tu sistema (`start.bat` o `start.sh`) desde [PowerNukkitX/scripts](https://github.com/PowerNukkitX/scripts).
    3. Sustituye tu jar antiguo por `powernukkitx.jar`. **Conserva** `nukkit.yml` y `server.properties` por ahora.
  </Step>
  <Step>
    ### Arranca el servidor

    PowerNukkitX encuentra `nukkit.yml` y `server.properties` y los migra:

    - copia ambos archivos en una nueva carpeta `backup/`;
    - lee todos sus ajustes y los escribe en `pnx.yml`;
    - borra los archivos antiguos y sigue arrancando.
  </Step>
</Steps>

## Adónde va cada ajuste

| Ajuste antiguo | Archivo antiguo | Sección de `pnx.yml` | Clave de `pnx.yml` |
| :-- | :-- | :-- | :-- |
| `server-ip` | `server.properties` | `baseSettings` | `ip` |
| `server-port` | `server.properties` | `baseSettings` | `port` |
| `max-players` | `server.properties` | `baseSettings` | `maxPlayers` |
| `level-name` | `server.properties` | `baseSettings` | `defaultLevelName` |
| `white-list` | `server.properties` | `baseSettings` | `allowList` |
| `xbox-auth` | `server.properties` | `baseSettings` | `xboxAuth` |
| `gamemode` | `server.properties` | `gameplaySettings` | `gamemode` |
| `difficulty` | `server.properties` | `gameplaySettings` | `difficulty` |
| `view-distance` | `server.properties` | `gameplaySettings` | `viewDistance` |
| `language` | `nukkit.yml` | `baseSettings` | `language` |
| `autosave` | `nukkit.yml` | `baseSettings` | `autosaveDelay` |
| `save-player-data` | `nukkit.yml` | `playerSettings` | `savePlayerData` |

## Plugins

Los plugins básicos de Nukkit suelen seguir funcionando, pero los que trabajan con los **registros de bloques, items o entidades** fallan: PowerNukkitX sustituyó esos registros por un sistema dinámico para admitir el contenido personalizado de Bedrock.

<Steps>
  <Step>Busca una versión para PowerNukkitX de cada plugin en el [hub de plugins](https://powernukkitx.org/plugins).</Step>
  <Step>Si no la hay, el plugin tiene que actualizarse o recompilarse contra la API de PowerNukkitX.</Step>
</Steps>
