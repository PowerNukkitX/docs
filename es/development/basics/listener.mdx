Un **listener** es una clase con métodos marcados con `@EventHandler`. Cuando el servidor lanza un evento de ese tipo, tu método se ejecuta.

<EventFlow />

<Tabs items={["Una clase listener", "En la clase principal"]}>
  <Tab value="Una clase listener">
    La forma ordenada para cualquier cosa que no sea un plugin diminuto:

    ```java title="JoinListener.java"
    package com.example.listener;

    import org.powernukkitx.Player;
    import org.powernukkitx.event.EventHandler;
    import org.powernukkitx.event.Listener;
    import org.powernukkitx.event.player.PlayerJoinEvent;

    public class JoinListener implements Listener {
        @EventHandler
        public void onJoin(PlayerJoinEvent event) {
            Player player = event.getPlayer();
            player.sendMessage("Welcome, " + player.getName() + "!");
        }
    }
    ```

    Regístrala cuando se active el plugin:

    ```java
    @Override
    public void onEnable() {
        this.getServer().getPluginManager().registerEvents(new JoinListener(), this);
    }
    ```

    <Callout type="info">
      O añade `@EventListener` a la clase y deja que el [procesador de anotaciones](/docs/es/development/basics/annotations) la registre.
    </Callout>
  </Tab>
  <Tab value="En la clase principal">
    Vale para un plugin pequeño: la clase principal es su propio listener.

    ```java title="ExamplePlugin.java"
    public class ExamplePlugin extends PluginBase implements Listener {
        @Override
        public void onEnable() {
            this.getServer().getPluginManager().registerEvents(this, this);
        }

        @EventHandler
        public void onJoin(PlayerJoinEvent event) {
            Player player = event.getPlayer();
            player.sendMessage("Welcome, " + player.getName() + "!");
        }
    }
    ```
  </Tab>
</Tabs>

## Cancelar un evento

La mayoría de los eventos se pueden cancelar: el servidor no hace entonces lo que anunciaba el evento. Aquí, solo los operadores pueden romper bloques:

```java
@EventHandler
public void onBreak(BlockBreakEvent event) {
    if (!event.getPlayer().isOp()) {
        event.setCancelled(true);
    }
}
```

Un evento se puede cancelar si su clase implementa `Cancellable`, como `BlockBreakEvent` y `PlayerChatEvent`.

## Orden y prioridad

Cuando varios handlers escuchan el mismo evento, se ejecutan por **prioridad**, de `LOWEST` a `MONITOR`. El que va después tiene la última palabra, porque puede deshacer lo que decidió uno anterior.

```java
@EventHandler(priority = EventPriority.HIGH, ignoreCancelled = true)
public void onChat(PlayerChatEvent event) {
    // runs after NORMAL handlers, and not at all if one of them cancelled the event
}
```

| Ajuste | Por defecto | Qué hace |
| :-- | :-- | :-- |
| `priority` | `NORMAL` | `LOWEST`, `LOW`, `NORMAL`, `HIGH`, `HIGHEST` y luego `MONITOR`. |
| `ignoreCancelled` | `false` | Si es `true`, el handler se salta cuando el evento ya está cancelado. |

<Callout type="warn">
  Usa `MONITOR` solo para observar el resultado final, para logs o estadísticas. No modifiques ahí el evento: otros plugins ya han actuado en consecuencia.
</Callout>
