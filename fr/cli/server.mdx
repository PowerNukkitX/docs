## init [#init]

Crée un serveur : un dossier, le jar de PowerNukkitX et les scripts de lancement. Alias : `new`, `create`.

```bash
pnx init
pnx init my-server
pnx init -y
pnx init survie --version v3.0.6
```

| Option | Effet |
| :-- | :-- |
| `[dossier]`, `--dir <chemin>` | Le dossier où créer le serveur. |
| `--version <tag>` | Un tag de version de PowerNukkitX, qui saute le choix de version. |
| `-y`, `--yes` | Prend toutes les valeurs par défaut sans rien demander : `./pnx-server` et la dernière version stable. |

Dans un terminal, elle demande ce qui manque ; dans un script (ou avec `--json`), elle tourne sans questions. Elle se termine comme `create-next-app` : les commandes utiles, puis les deux lignes exactes à taper ensuite (`cd my-server`, `pnx start`). Le jar vient des versions GitHub de PowerNukkitX et les scripts de [PowerNukkitX/scripts](https://github.com/PowerNukkitX/scripts). Le nouveau serveur devient le serveur par défaut.

## start [#start]

Démarre le serveur au premier plan, avec les options Java dont PowerNukkitX a besoin. Alias : `run`, `up`.

```bash
pnx start
pnx start -m 4G --restart
pnx start ./my-server
pnx start --dry-run
```

| Option | Effet |
| :-- | :-- |
| `[dossier]`, `--dir <chemin>` | Le dossier du serveur, au lieu du serveur par défaut. |
| `-m`, `--memory <taille>` | La mémoire maximale du serveur (`2G`, `4G`, `3072M`...), `2G` par défaut. |
| `-r`, `--restart` | Relance le serveur après un crash, 3 fois en 10 minutes au plus. |
| `-V`, `--verbose` | Affiche tout le log de démarrage au lieu de l'animation. |
| `--dry-run` | Affiche la commande `java` au lieu de l'exécuter. |

Le démarrage se lit comme `next dev` : un en-tête avec la version de PowerNukkitX et les adresses de connexion, une seule animation pendant le démarrage, puis le moment où les joueurs peuvent se connecter.

```
  ◆ PowerNukkitX 3.0.6
  - Local:    127.0.0.1:19132
  - Network:  192.168.1.15:19132
  - Java:     25 (Temurin) · up to 2G
  - Folder:   /srv/minecraft

✓ Ready in 3.1s · 3 warnings (pnx logs)
  Type a server command here · Ctrl+C or `pnx stop` saves and stops
```

Les erreurs pendant le démarrage s'affichent quand même au fil de l'eau, et un démarrage raté montre les dernières lignes du log. Dans un pipe ou sous un gestionnaire de services (systemd, Docker), le log passe tel quel.

`--memory` est le plafond du tas (`-Xmx`) ; le tas démarre au quart de cette valeur, pour ne pas vider une petite machine au démarrage. Java tourne en UTF-8 partout, avec le ramasse-miettes ZGC et les options `--add-opens` dont PowerNukkitX a besoin, depuis `JAVA_HOME` quand il est défini.

Ce que vous tapez dans ce terminal arrive dans la console du serveur. **Ctrl+C** tape `stop` à votre place, donc le monde est sauvegardé ; un second Ctrl+C force l'arrêt.

## stop [#stop]

Sauvegarde le monde et arrête le serveur lancé par `pnx start`, depuis n'importe quel terminal. Alias : `down`.

```bash
pnx stop
pnx stop --force
```

`pnx stop` tape `stop` dans la console du serveur : les joueurs le voient et rien n'est perdu. `-f`, `--force` tue le processus à la place : ce qui n'était pas encore sauvegardé est perdu.

## cmd [#cmd]

Tape une commande dans la console du serveur en marche, depuis n'importe quel terminal. Sans RCON. Alias : `send`, `exec`.

```bash
pnx cmd say Redémarrage dans 5 minutes
pnx cmd op Steve
pnx cmd save-all
```

La réponse s'affiche dans la fenêtre du serveur et dans son log (`pnx logs`).

## status [#status]

Un coup d'œil sur ce qui se passe : le serveur tourne-t-il, depuis quand, et à quelles adresses les joueurs se connectent. Alias : `ps`.

```bash
pnx status
pnx --json status
```

Elle affiche l'état (PID et durée de fonctionnement quand il tourne), le port UDP lu dans `pnx.yml`, le nombre de plugins et de mondes, l'âge de la dernière sauvegarde, et chaque adresse de connexion : `127.0.0.1` sur cette machine, et chaque adresse du réseau local pour les joueurs du même réseau.

<Callout type="info">
  Pour les joueurs hors de votre réseau, redirigez ce port UDP sur votre box et donnez-leur votre adresse publique. Voir [Mise en ligne](/docs/fr/administration/go-live).
</Callout>

## console [#console]

Ouvre une console vers un serveur en marche, via **RCON**. Pour un serveur démarré avec `pnx start`, [`pnx cmd`](#cmd) se passe de RCON.

```bash
pnx console
```

Elle lit `enable-rcon`, `rcon.port` (`25575` par défaut) et `rcon.password` dans le `server.properties` du serveur. RCON est désactivé par défaut ; dans ce cas, `pnx console` vous dit quoi activer. Tapez `exit` pour sortir.

## logs [#logs]

Affiche le log du serveur et continue de le suivre. Alias : `log`.

```bash
pnx logs
pnx logs --lines 200
pnx logs --no-follow
```

| Option | Effet |
| :-- | :-- |
| `-n`, `--lines <n>` | Combien de lignes afficher d'abord. |
| `--follow` | Continue d'afficher les nouvelles lignes au fur et à mesure. `--no-follow` affiche puis quitte. |

## config [#config]

Affiche la configuration que lit le serveur (`pnx.yml`, ou l'ancien `server.properties`), pour vérifier une valeur sans ouvrir le fichier.

```bash
pnx config
pnx --json config
```

### config get / config set [#config-get]

Lit ou modifie **une** valeur par sa clé pointée. `set` ne réécrit que la valeur sur cette ligne : chaque commentaire et la mise en page du fichier restent intacts.

```bash
pnx config get settings.port
pnx config set settings.maxPlayers 50
pnx config set settings.motd "Survie"
pnx config set allowList true
```

Le dernier segment suffit s'il est unique (`motd` pour `settings.motd`), et une clé mal orthographiée reçoit une suggestion. `get` affiche la valeur brute, prête pour un script : `PORT=$(pnx config get port)`. Redémarrez le serveur pour appliquer un changement. Les listes et blocs imbriqués restent l'affaire d'un éditeur : `pnx open config`.

## open [#open]

Ouvre le dossier du serveur, ou une partie, dans le gestionnaire de fichiers ou l'éditeur du système.

```bash
pnx open
pnx open config
pnx open plugins
```

Accepte `folder` (par défaut), `config`, `logs`, `plugins`, `backups` et `worlds`. Avec `--json`, elle affiche le chemin au lieu de l'ouvrir.

## use [#use]

Choisit le serveur sur lequel agissent toutes les commandes.

```bash
pnx use
pnx use ./my-server
pnx use --clear
```

Sans dossier, elle liste les serveurs qu'elle trouve et vous laisse choisir. `--clear` oublie à nouveau le serveur par défaut.
