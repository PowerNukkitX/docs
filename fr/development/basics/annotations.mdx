**PNX-APT** est un processeur d'annotations à la compilation. Annotez vos classes et, à la compilation, il :

<Steps>
  <Step>génère le descripteur `powernukkitx.yml` dans votre jar ;</Step>
  <Step>génère une classe `PNXPluginBootstrap` qui enregistre vos commandes, listeners et tâches ;</Step>
  <Step>exécute ce bootstrap quand votre plugin est activé.</Step>
</Steps>

Plus de `plugin.yml` à écrire, plus d'appels `registerEvents` à penser.

## Métadonnées du plugin : `@PluginMeta`

Placez-la sur votre **unique** classe principale, celle qui étend `PluginBase` :

```java title="MyPlugin.java"
package org.example;

import org.powernukkitx.plugin.PluginBase;
import org.powernukkitx.plugin.PluginLoadOrder;
import org.powernukkitx.plugin.annotation.PluginMeta;

@PluginMeta(
    name = "MyPlugin",
    version = "1.0.0",
    api = {"3.0.0-SNAPSHOT"},
    authors = {"AuthorName"},
    description = "An automated plugin using annotations!",
    website = "https://example.com",
    order = PluginLoadOrder.POSTWORLD
)
public class MyPlugin extends PluginBase {
    // pas de plugin.yml ni de powernukkitx.yml à écrire
}
```

| Paramètre | Type | |
| :-- | :-- | :-- |
| `name` | `String` | Le nom du plugin. |
| `version` | `String` | Sa version. |
| `api` | `String[]` | Les versions d'API PowerNukkitX compatibles, par exemple `{"3.0.0-SNAPSHOT"}`. |
| `authors` | `String[]` | Facultatif. Les auteurs. |
| `description` | `String` | Facultatif. Une description. |
| `website` | `String` | Facultatif. Un site web. |
| `prefix` | `String` | Facultatif. Un préfixe de log personnalisé. |
| `depend` | `String[]` | Facultatif. Les plugins à charger avant, obligatoirement. |
| `softDepend` | `String[]` | Facultatif. Les plugins chargés avant s'ils sont présents. |
| `loadBefore` | `String[]` | Facultatif. Les plugins chargés après celui-ci. |
| `order` | `PluginLoadOrder` | Facultatif. `POSTWORLD` (par défaut) ou `STARTUP`. |

## Listeners: `@EventListener`

Au lieu d'appeler `registerEvents(...)` dans `onEnable()` :

```java title="MyListener.java"
package org.example;

import org.powernukkitx.event.EventHandler;
import org.powernukkitx.event.Listener;
import org.powernukkitx.event.player.PlayerJoinEvent;
import org.powernukkitx.plugin.annotation.EventListener;

@EventListener
public class MyListener implements Listener {
    @EventHandler
    public void onJoin(PlayerJoinEvent event) {
        event.getPlayer().sendMessage("Welcome to the server!");
    }
}
```

## Tâches : `@ScheduleTask`

Sur une classe `Runnable` (ou `Task`), ou sur une méthode `public static` :

| Option | Défaut | |
| :-- | :-- | :-- |
| `delay` | `0` | Ticks avant la première exécution. |
| `period` | `0` | Ticks entre deux exécutions. `0` l'exécute une fois. |
| `async` | `false` | S'exécute hors du thread principal. |

<Tabs items={["Sur une classe", "Sur une méthode"]}>
  <Tab value="Sur une classe">
    ```java title="MyTask.java"
    import org.powernukkitx.plugin.annotation.ScheduleTask;

    @ScheduleTask(delay = 100, period = 200, async = false)
    public class MyTask implements Runnable {
        @Override
        public void run() {
            System.out.println("Toutes les 10 secondes !");
        }
    }
    ```
  </Tab>
  <Tab value="Sur une méthode">
    ```java title="StaticTasks.java"
    import org.powernukkitx.plugin.annotation.ScheduleTask;

    public class StaticTasks {
        @ScheduleTask(delay = 20, async = true)
        public static void runOnceAsync() {
            System.out.println("Une fois, en asynchrone, après 1 seconde !");
        }
    }
    ```
  </Tab>
</Tabs>

## Commandes : `@CommandDefinition`

Enregistre la commande dans la table de commandes du serveur. `commandMode` choisit comment les arguments sont routés :

```java title="MyCommand.java"
import org.powernukkitx.command.Command;
import org.powernukkitx.plugin.annotation.CommandDefinition;
import org.powernukkitx.plugin.annotation.CommandDefinition.CommandMode;

@CommandDefinition(
    name = "mycommand",
    description = "An annotation-registered command",
    usage = "/mycommand",
    aliases = {"mycmd"},
    permission = "myplugin.command.use",
    commandMode = CommandMode.COMMAND_TREE
)
public class MyCommand extends Command {
    // COMMAND_TREE: override buildCommandTree(RouteTree tree)
    // RAW: override execute(CommandSender sender, String label, String[] args)
}
```

| Mode | |
| :-- | :-- |
| `COMMAND_TREE` (par défaut) | L'arbre de routage fluide : surchargez `buildCommandTree(RouteTree tree)`. Voir [Commandes](/docs/fr/development/basics/commands). |
| `PARAM_TREE` | L'API de paramètres par sous-commandes. |
| `RAW` | Pas de routage automatique : analysez vous-même les arguments dans `execute`. |
