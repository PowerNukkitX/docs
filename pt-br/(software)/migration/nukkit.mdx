Esta é a migração mais fácil: o PowerNukkitX lê sua configuração antiga e a converte na primeira inicialização.

## Passos

<Steps>
  <Step>
    ### Faça backup

    Copie a pasta inteira do servidor para um lugar seguro.
  </Step>
  <Step>
    ### Substitua os arquivos

    1. Baixe o `powernukkitx.jar` mais recente nas [releases](https://github.com/PowerNukkitX/PowerNukkitX/releases).
    2. Baixe o script de inicialização do seu sistema (`start.bat` ou `start.sh`) em [PowerNukkitX/scripts](https://github.com/PowerNukkitX/scripts).
    3. Troque o jar antigo pelo `powernukkitx.jar`. **Mantenha** `nukkit.yml` e `server.properties` por enquanto.
  </Step>
  <Step>
    ### Inicie o servidor

    O PowerNukkitX encontra `nukkit.yml` e `server.properties` e os migra:

    - copia os dois arquivos para uma nova pasta `backup/`;
    - lê todas as configurações deles e as grava no `pnx.yml`;
    - apaga os arquivos antigos e continua iniciando.
  </Step>
</Steps>

## Para onde vai cada configuração

| Configuração antiga | Arquivo antigo | Seção do `pnx.yml` | Chave do `pnx.yml` |
| :-- | :-- | :-- | :-- |
| `server-ip` | `server.properties` | `baseSettings` | `ip` |
| `server-port` | `server.properties` | `baseSettings` | `port` |
| `max-players` | `server.properties` | `baseSettings` | `maxPlayers` |
| `level-name` | `server.properties` | `baseSettings` | `defaultLevelName` |
| `white-list` | `server.properties` | `baseSettings` | `allowList` |
| `xbox-auth` | `server.properties` | `baseSettings` | `xboxAuth` |
| `gamemode` | `server.properties` | `gameplaySettings` | `gamemode` |
| `difficulty` | `server.properties` | `gameplaySettings` | `difficulty` |
| `view-distance` | `server.properties` | `gameplaySettings` | `viewDistance` |
| `language` | `nukkit.yml` | `baseSettings` | `language` |
| `autosave` | `nukkit.yml` | `baseSettings` | `autosaveDelay` |
| `save-player-data` | `nukkit.yml` | `playerSettings` | `savePlayerData` |

## Plugins

Plugins básicos do Nukkit costumam continuar funcionando, mas os que trabalham com os **registros de blocos, itens ou entidades** falham: o PowerNukkitX trocou esses registros por um sistema dinâmico para suportar o conteúdo personalizado do Bedrock.

<Steps>
  <Step>Procure uma versão para PowerNukkitX de cada plugin no [hub de plugins](https://powernukkitx.org/plugins).</Step>
  <Step>Se não houver, o plugin precisa ser atualizado ou recompilado com a API do PowerNukkitX.</Step>
</Steps>
