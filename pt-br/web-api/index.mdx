O hub em [powernukkitx.org](https://powernukkitx.org) tem uma API JSON em `/api/v1`. É a mesma API que o site, a [CLI](/docs/pt-br/cli) e o [Assistant](/docs/pt-br/assistant) usam para buscar plugins e baixar versões aprovadas. Tudo nestas páginas é **somente leitura** e funciona sem conta.

<ApiFlow />

## URL base

```text
https://powernukkitx.org/api/v1
```

Todo endpoint responde a `GET` com um documento JSON, exceto o emblema do plugin, que é uma imagem SVG, e o feed pessoal, que é XML Atom.

```bash
curl "https://powernukkitx.org/api/v1/plugins?q=economy&sort=downloads"
```

## Tokens

Um token é opcional. Ele identifica suas chamadas para que tenham um orçamento próprio, maior que o anônimo. Ele **não libera nenhum dado a mais**: tudo o que um token lê, uma requisição anônima também lê.

<Steps>
  <Step>Entre em powernukkitx.org com o GitHub.</Step>
  <Step>Abra **Dashboard > Settings > Feed and API** e crie um. Você pode ter até 10.</Step>
  <Step>Copie na hora: ele aparece uma única vez, e só um hash é guardado.</Step>
  <Step>Envie-o no cabeçalho `Authorization`.</Step>
</Steps>

```bash
curl -H "Authorization: Bearer pnx_<keyId>_<secret>" \
  "https://powernukkitx.org/api/v1/plugins"
```

Um token é `pnx_` seguido de um id de 12 caracteres, um sublinhado e um segredo de 64 caracteres. Um token malformado, desconhecido ou revogado recebe `401 invalid_token`: ele nunca cai em silêncio para o orçamento anônimo.

<Callout type="warn">
  Mantenha tokens fora de repositórios públicos e de código que roda no cliente. Um token vazado não consegue mudar nada, mas outra pessoa pode gastar o orçamento dele. Revogue-o na mesma página de configurações.
</Callout>

## Limites de uso

Os orçamentos são contados por minuto.

| Quem chama | Orçamento | Contado em |
| :-- | :-- | :-- |
| Anônimo | 240 requisições por minuto | Seu endereço IP |
| Com token | 600 requisições por minuto | O token |
| Lista de servidores, downloads de plugins | 60 requisições por minuto | Seu endereço IP |

Acima do orçamento, a API responde `429` com um cabeçalho `Retry-After` que diz quantos segundos esperar.

## Erros

Os erros são JSON com um código `error`:

```json
{ "error": "invalid_query", "issues": [] }
```

| Status | Quando |
| :-- | :-- |
| `400` | Um parâmetro da consulta não passou na validação. `issues` diz qual. |
| `401` | O token não foi reconhecido ou foi revogado. |
| `403` | A versão existe, mas não foi aprovada (downloads). |
| `404` | Esse plugin ou servidor não existe, ou não está publicado. |
| `429` | Orçamento esgotado. Espere `Retry-After` segundos. |

## Cache

As listas ficam em cache por um minuto na borda da rede, e os dados que mudam menos (servidores, coleções, avisos) por dez minutos. As respostas trazem um `ETag`: um cliente que envia `If-None-Match` recebe um `304` sem corpo quando nada mudou.
