先做第一项检查，再展开与你看到的情况相符的问题。

<Callout type="info" title="先检查 Java">
  运行 `java -version`。它必须显示 **21 或更高**：PowerNukkitX 需要 Java 21+（参见[系统要求](/docs/zh/requirements)）。
</Callout>

## Java

<Accordions>
  <Accordion title="UnsupportedClassVersionError">
    ```text
    java.lang.UnsupportedClassVersionError: org.powernukkitx/Nukkit has been compiled by a more
    recent version of the Java Runtime (class file version 65.0), this version of the Java
    Runtime only recognizes class file versions up to ...
    ```

    你的 Java 太旧：类文件版本 `65.0` 对应 Java 21。请安装 Java 21 或更高版本，并用 `java -version` 检查。
  </Accordion>
  <Accordion title="安装了多个 Java 版本">
    很可能排在前面的是错误的版本。可以：

    - 把 `JAVA_HOME` 设为你的 Java 21+ 安装目录，并把它的 `bin` 文件夹放在 `PATH` 的最前面；
    - 或者用正确 Java 的完整路径启动服务器：

    ```bash
    /path/to/jdk-21/bin/java -jar powernukkitx.jar
    ```

    在 Linux 上，用 `sudo update-alternatives --config java` 切换默认版本。在 Windows 上，确认系统环境变量中的 `JAVA_HOME` 指向 JDK 21+ 文件夹。
  </Accordion>
  <Accordion title="32 位 Java">
    PowerNukkitX 需要 **64 位** Java：32 位 JVM 无法使用足够的内存，在高负载下会崩溃。如果 `java -version` 中出现 `Client VM` 或 `32-Bit`，请安装 64 位 OpenJDK。
  </Accordion>
</Accordions>

## 启动

<Accordions>
  <Accordion title="BindException: Address already in use">
    其他程序已经占用了服务器端口（默认 `19132/UDP`）。停止其他基岩版服务器，或在 `pnx.yml` 的 `baseSettings` 中修改 `port`。
  </Accordion>
  <Accordion title="OutOfMemoryError，或服务器立即退出">
    服务器可能内存不足。用明确的内存上限启动，并给系统留出空间：

    ```bash
    java -Xms1G -Xmx2G -jar powernukkitx.jar
    ```
  </Accordion>
  <Accordion title="首次启动时缺少文件或出现权限错误">
    首次启动时，PowerNukkitX 会在它的文件夹中创建世界和配置。请在专用且可写的文件夹中运行，而不是系统文件夹或只读文件夹。在 Linux 和 macOS 上，确保 jar 和文件夹归你的用户所有（`chown`、`chmod`）。
  </Accordion>
  <Accordion title="服务器已启动，但没人能连接">
    - 检查客户端和服务器的版本是否一致。
    - 在防火墙和路由器上开放或转发 UDP 端口 `19132`。
    - 在同一台机器上，连接 `127.0.0.1` 或 `localhost`。
  </Accordion>
</Accordions>
